## 발견 및 국소 수정

### 중요 조작부 경계 대비 미달 — 지정 CSS 테마색으로 재현

입력/선택/텍스트영역, 기본 보조 버튼/과초점 버튼, range 트랙이 장식용 구분선 `--pfm-line`을 공유했다. 지정된 테마색을 sRGB 선형 휘도 공식으로 계산하면 사용자가 요청한 중요 경계3:1에 못 미쳤다.

| 지정 테마/주변색 | 수정 전 | 수정 후 | 기준 |
| --- | --- | --- | --- |
| 라이트 페이지 #f5f1e8 |1.63:1 |3.63:1 |3:1 |
| 라이트 입력 표면 #fffdf7 |1.80:1 |4.03:1 |3:1 |
| 다크 페이지 #1c1d20 |2.45:1 |4.87:1 |3:1 |
| 다크 입력 표면 #26282d |2.14:1 |4.27:1 |3:1 |

수정: 장식용 선은 유지하고 `--pfm-control-line`만 추가(라이트#827d72/다크#858a96). 중요한 조작 경계와 range 트랙에 한정해 연결했다. 배경·주요 팔레트·간격·도형·숫자·장면 크기를 바꾸지 않았다. CSS131바이트 증가, JS 증가 없음.

증거: `contrast-before.json`, `contrast-after.json`. 새 CSS 계약 검사에서 수정 전1개 실패/52개 통과, 수정 후53개 모두 통과. 일반/보조/오류/경고 글씨와 기본 동작 버튼은4.5:1, 포커스 색은3:1 기준으로 지정 토큰을 검사했다. 모든 선택자의 플러그인 범위 제한과 외부 스타일/자산 import 없음도 검사했다.

이는 **렌더링된 픽셀·호스트 스타일·서드파티 테마까지 검사한 접근성 인증이 아니라 코드에 지정된 테마색의 수치 검사**다. 수정 후 실제 화면의 선명도·간격/가림 등은 새 캡처에서 확인해야 한다. 캡처를 얻지 못해 수정 전후 화면 증거는 없음.

### 실제 번들 통합 검사의 정확한 의미

통과한15개:

## 코드 검사와 미검증 구분

- JS는 최신 바우하우스 커밋과 동일하고 기존53개 수치·마이그레이션·노트·쓰기·번들 테스트가 통과하므로 UI 입력/제스처 동작을 이유 없이 바꾸지 않았다.
- production `paint()`는 결과를 갱신하며 숫자 입력의 전체 render를 호출하지 않는 기존 구조와 포커스 중 GN 재대입 방지 조건을 유지한다. **이번에는40.5/540·거리/조리개/CoC 커서·선택 범위·스크롤을 실제 화면에서 재현하지 못했다.**
- 프리셋 초안의 데이터 복원은 코드 통합에서 통과했다. 펼친 details, 화면 닫기/재진입, 피사체 포인터·슬라이더/세로 스크롤/사이드바, 빠른 탭, 저장 버튼 중복과 disabled 상태, 실제 도구막대 겹침은 새 UI 검사 미수행.
- no-overflow/44px CSS 선언과 기존 화면은 읽었지만360/390세로·844×390가로·큰 글씨·좁은 가용 높이에서 **이번 실제 렌더링 통과를 주장하지 않는다**.
- 스코프 계약은 모든 CSS 선택자가 `.pfm-root`/`.pfm-container` 안에 있는지 검사했다. 다른 노트의 실제 computed style 비교는 실행하지 못했다.
- source 색과 범위/축 코드는 바꾸지 않았다. 장면 좌표·드래그에 대한 기존 단위 검사는 통과했으나 색/라벨의 겹침과 물리 의미를 현재 화면에서 시각 확인하지 못했다.
- 저장 중 종료/강제 종료/전원 상실의 완전 보존은 검사/보장 대상이 아니다. 실사용 앱을 종료하지 않았다.
