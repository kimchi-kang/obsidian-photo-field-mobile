## 2. 발견·수정한 문제와 증거

### GN 소수 입력이 다른 숫자로 바뀜

수정 전 실제 테스트 화면에서 GN 전체 삭제 후 `4 → 0 → . → 5` 키 입력. inputValue 관찰값은 `4 → 40 → 40 → 540`, 기대값40.5. GN40.50 전체 입력도40.5로 즉시 재작성됐다. `paint()`가 매 입력마다 GN/측정 줌/최소 출력의 input.value를 다시 지정하여 입력 문자열과 커서 위치가 바뀌었다. 의도한 GN보다 큰 거리 계산으로 이어질 수 있다.

수정: 결과 갱신 시 현재 포커스가 있는 숫자 칸은 재대입하지 않는다. 장비·줌·단위 변경으로 필요한 다른 칸의 갱신은 유지. 새 화면 회귀 검사에서 소수 키 연속 입력40.5/40.25, 전체 삭제, 재입력, 포커스 유지 통과. 거리5.25·CoC0.029와 재활성화 후 복원도 확인. 이는 Chromium 입력 동작이며 실기 숫자 키보드 통과는 아니다.

### 유효한 심도 결과를 플래시 조건 때문에 저장할 수 없음

수정 전 `tab=dof, mode=hss, gn=0`: 심도4.07/6.48/2.41m, 과초점21.72m가 정상 표시됐지만 전체 검증의 플래시 오류로 저장 거부. 이전 전체 스냅샷 정책은 의도된 동작이었으나 심도만 확인·보관하려는 흐름과 충돌했다.

수정: **현재 탭 결과 저장**과 **전체 계산을 노트로 저장** 버튼/명령을 구분. 심도 탭은 유효한 심도·화각만 검증/저장하고 GN·플래시·조사 범위 결과는 제외한다. 플래시 탭은 플래시 결과만 검증/저장하고 광학·조사 범위는 제외한다. 통합 탭 또는 전체 저장은 기존 전체 검증을 유지한다. Markdown에 저장 범위를 명시한다. 탭 저장도 해당 계산이 무효이면 새 노트를 만들기 전에 거부한다.

새 단위 검사4개와 화면 시나리오에서 미지원HSS/줌GN 누락에도 유효한 심도 저장, 전체 저장 거부, 무효 광학 거부, 플래시 이론 출력 표시, 전체 결과 유지 확인. 유효하지 않은 제외 계산을 정상 결과로 기록하지 않는다.

수정 전 관찰: [before.json](before.json). 수정 후 흐름별 결과: [results.json](results.json). 로컬 화면 증거(공개 Git 제외): `../screenshots/preparation-before.png`, `preparation-dof.png`, `preparation-save.png`. 저장 버튼 화면은360×420·rem20px 대리 조건에서 직접 확인했으며 문구·버튼 잘림 없음. 촬영 장면과 기존 스타일은 유지했다.

## 5. 사용자 기기 잔여 확인과 실제 장비 비교

[8~10분 실기 체크리스트](DEVICE-CHECKLIST.md)에 각 조작 순서·기대 결과·실패 기록을 제공했다. 실제 소수 키보드/IME·중간 커서, 키보드 가림/열린 채 회전, 노치·안전영역·시스템 큰 글씨, Android 뒤로가기, WebKit/WebView 제스처, 실제 배경 복귀·저장 완료 후 모바일 재실행·오프라인 파일 쓰기는 미확인이다. macOS 축소 뷰포트/20px rem 검사는 그 대체 통과가 아니다.

장비 모델·설명서·실측값이 없어 실제 장비 프리셋은 생성하지 않았다. [장비 비교 기록 양식](EQUIPMENT-COMPARISON.md)에 GN 출처/기준 줌, 출력·ISO·조리개·거리, 직광·일반 동조/손실, 계산 예상값, 확인한 측정값과 촬영 관찰, 오차/미확인 조건을 분리했다. GN으로 절대 조도·사진 밝기를 확정하거나 사진 밝기만으로 자동 보정하지 않는다.

최소1.7.4는 기존 API·공식 앱 코드 근거를 유지. **그 버전에서 실행하지 않았다.** 실행 확인은1.14.5 macOS뿐이다.
