# 현장 연속 사용 검사 · 2026-11-03

기준은 공개·설치가 완료된 **1.4.0, df1a6fb**의 실제 구현이다. 이번 수정은 **1.4.1 설치 후보**로만 준비했다. 실사용 보관함·공개 배포는 변경하지 않았다. 새 기능·계산 엔진·장비 사양·CSS 디자인을 추가하거나 재작성하지 않았다.

## 검사 범위와 방법

macOS Obsidian 1.14.5의 별도 `/private/tmp/photo-field-qa-vault`, 별도 사용자 프로필 `/private/tmp/photo-field-qa-profile`, CDP 9338에서 실제 플러그인 ItemView를 열었다. `app.emulateMobile(true)`와 Playwright/CDP 터치 입력을 사용했으며 iPhone 미러링은 사용하지 않았다. 초기 가상 데이터 준비 뒤에는 내부 상태를 대입하지 않고 화면 버튼·입력·터치를 사용했다. 내부 접근은 결과·저장 파일·해시 검증에만 사용했다.

수정 전/후 각각 초기 준비 한 번 뒤 야간→존→근거리→오프카메라→중단/노트/재진입을 이어 수행했다. 이후 오류 복구·12개 화면 조합·취소 연속 동작도 같은 상태에서 이어 검사했다. 최종 정상 앱 종료·재실행에서 마지막 설정·즐겨찾기·장비 복원과 거리 한 번으로 조작 재개를 확인했다. 관찰 연결이 한 차례 응답하지 않아 QA 프로필 프로세스만 확인 후 재연결한 이력이 있으며, 이를 실제 앱 멈춤으로 판정하지 않았다. 최종 정상 재실행 검사는 별도로 통과했다.

사용자 소유가 프로젝트에 명시된 장비는 [Q20III 기록](../q20iii/REPORT.md)의 LightPix Labs FlashQ Q20III다. 프로젝트에 있는 제조사 명목 GN20m/ISO100·32mm 고정 조사각·지원 출력 목록을 사용했다. 실측값이 아니다. 카메라·렌즈·센서·거리·촬영 즐겨찾기·존 목표는 **가상 테스트 조건**이며 실사용 데이터를 통째로 복사하지 않았다.

## 연속 상황과 실제 조작 기록

탭은 버튼·입력칸·선택 동작 기록 기준이다. 입력 포커스는 키보드가 필요해지는 지점 수이며, macOS 에뮬레이션에서 실제 iOS/Android 화면 키보드를 관찰한 횟수가 아니다. 스크롤은 다음 조작에 도달하기 위해 발생한 이동 기록이고, 왕복은 하향 이동 다음 상향 이동 한 쌍으로 집계했다. 자동 포커스 이동은 원본 사건 기록에 따로 남겼다. 자동화 시간을 숙련도·사용자 연구 결과로 해석하지 않았다.

| 연속 상황 | 결과 | 탭 전→후 | 도달 스크롤 전→후 | 왕복 전→후 | 입력 포커스 전→후 |
|---|---|---:|---:|---:|---:|
| 야간: 즐겨찾기→1/2/3m→권장 적용→약하게→역방향 복구→다른 즐겨찾기 | 통과, 수동 조절 후 취소 제한 있음 | 8→8 | 2→2 | 1→1 | 0→0 |
| 존: 2~5m→적용→3m~∞→적용→50mm 재계산→85mm 불가→제한 확인→28mm 복구 | 통과 | 21→19 | 7→6 | 3→3 | 3→3 |

| 오프카메라: 카메라와 플래시 분리→거리 버튼→화면 전환→온카메라 연동 | 통과 | 11→11 | 4→4 | 2→2 | 1→1 |

이는 여러 거리를 시험하고 잘못된 조건을 복구한 **전체 상황의 조작 수**다. 단일 기본 경로인 “촬영 즐겨찾기→거리 하나→권장 출력 적용”은 3탭이며 EV 확인은 추가 탭이 없다. 거리 버튼·출력 단계·조리개 ± 조작에 텍스트 입력 포커스가 필요하지 않았다. 360px에서 긴 장비명과 거리 여섯 개를 사용하면 결과와 즐겨찾기 사이 왕복이 남는다. 이 불편을 없앴다고 주장하지 않는다.

## 우선순위별 불편 5개와 최소 수정

1. **실제 파일 저장 실패가 성공처럼 처리됨.** Obsidian의 `saveData`가 하위 파일 쓰기 오류를 삼키는 동작을 확인했다. QA의 `data.json`만 잠시 디렉터리로 바꿔 EISDIR를 발생시켰을 때 기존 화면은 저장 오류를 표시하지 않았다. 파일을 복원하고 저장 재시도로 복구했다. 이제 저장 직후 파일을 읽어 현재 저장 내용과 일치하는지 확인하고 기존 오류·재시도 UI로 연결한다. 기존 병합·최신값 재시도는 유지한다. [이전 증거](before/silent-save-failure.json), [이전 화면](before/24-silent-save-failure.png), [수정 화면](after/23-save-failure.png).
2. **간편 존 화면의 렌즈 한계 확인이 보이지 않는 상세 영역만 열었음.** 버튼 한 번으로 기존 상세 화면의 실제 조리개 상한을 펼쳐 화면 중앙에 보이게 했다. 입력칸 대신 그룹에 초점을 주어 키보드를 요구하지 않는다. 촬영값은 바꾸지 않는다. 동일 전체 상황 21→19탭, 도달 스크롤 7→6회. [이전](before/05-zone-limits-click.png), [수정](after/06-zone-limits.png).
3. **장비에 없는 줌의 GN을 수동 GN 입력 문제로 안내함.** Q20III에서 50mm를 선택하면 정확히 50mm GN 자료 누락과 사용 가능 32mm를 표시하고 기존 장비 줌 설정으로 이동한다. 계산은 차단하며 오래된 GN을 사용하지 않는다. [이전](before/20-missing-zoom.png), [수정](after/20-missing-zoom.png).
4. **거리 더보기가 다음 촬영 상황까지 열린 채 결과를 밀어냄.** 거리를 적용하면 더보기를 접는다. 선택한 내부 m 값과 대상은 유지한다. 근거리 상황 도달 스크롤 3→2회. 오프카메라 결과 화면에서도 불필요한 펼침이 줄었다. [이전](before/11-off-camera.png), [수정](after/11-off-camera.png).
5. **권장 출력 취소의 범위·만료 표시가 모호하고 새 적용 뒤에도 과거 만료 문구가 남음.** 버튼을 “권장 출력 적용 취소”로 명시하고 만료 요약을 짧게 했다. 새 권장 적용은 과거 권장 취소 만료 안내만 제거한다. 새 유효 취소와 만료 안내가 함께 표시되던 재현은 수정 중 추가 발견한 것이므로 아래 이전 캡처는 중간 1.4.1 빌드다. [추가 재현](before/26-new-recommendation-undo.png), [최종 수정](after/26-new-recommendation-undo.png), [검사](after/undo-continuation.json).

수동 약하게/강하게 이후에는 기존 권장 적용 취소가 만료되는 안전 정책을 유지했다. 사용자가 의도한 “수동 변경 직전으로 취소”는 현재 제공되지 않는다. 이번 검사에서는 반대 방향 지원 단계로 복구하고, 별도로 새 권장 적용 직후의 명시적 취소를 검증했다. 일반적인 수동 단계 실행 취소는 새 기능이므로 이번에 추가하지 않았다.

## 화면·계산 결과 확인

360×800·390×844 세로, 844×390 가로 × 라이트/다크 × 기본/루트 22px 큰 글씨 = **12개 조합**, 각 플래시·렌즈 제한·존 결과 **36개 캡처**를 생성하고 대표 화면을 직접 확인했다. [전체 결과](after/matrix.json). 가로 넘침 없음, 검사한 플러그인 버튼·summary 높이 43.5px 이상, 렌즈 제한 입력 대상이 상하 앱 조작 막대에 가리지 않음을 확인했다. 조작 요소에 도달하기 위한 스크롤이 필요한 화면은 남는다. 장면은 기존 동작하는 촬영 SVG를 유지했다.

실제 스타일 기준 주요 글자 대비는 라이트 14.36:1·다크 14.51:1, 조건 요약은 5.91:1·8.49:1이다. 조건 요약 글씨는 기본 13px·큰 글씨 17.875px이다. 전체 접근성 인증이나 야외 가독성 결과가 아니다. [360px 다크 큰 글씨 제한](after/matrix-360-800-dark-large-limits.png), [가로 제한](after/matrix-844-390-light-normal-limits.png), [센서 환산 구별](after/25-sensor-equivalence.png).

- 권장/현재 출력, 적용 후 잔여 EV, 최소 출력 한계가 따로 표시된다. 1/64에서도 남는 +0.64EV처럼 장비로 해결하지 못하는 잔여 차이를 숨기지 않는다. 실제 장비를 제어하거나 거리를 측정하지 않는다.
- 실제 조리개와 심도 환산 조리개를 구별하고 MFT 센서 변경 시 실제 조리개·ISO·출력·거리 불변을 확인했다. 존은 35→50→85→28mm와 센서 변경 뒤 현재 조건으로 다시 계산했다. 목표만 선택해서 실제 촬영값을 자동 변경하지 않는다.
- 50/80cm·1.2m 버튼은 m 내부값을 사용하고 직접 입력 55cm→50cm에서 단위·커서가 유지됐다. 28mm 렌즈에 2cm 같은 박막렌즈 불가능 조건은 차단된다. 실제 렌즈 최소 초점거리·근거리 플래시 정확도는 장비 자료/실기가 필요하며 임의 기준을 추가하지 않았다.
- 오프카메라 거리 버튼은 플래시 거리만 변경하고 카메라 50cm는 유지했다. 간편↔상세 입력/결과가 같고 온카메라 복귀는 다시 연동됐다.

## 관련 회귀와 한계

최종 현재 빌드에 대해 strict TypeScript·빌드, 자동 **95/95**, 실제 연속 상황 4개+중단/노트/정상 재시작, 오류/저장 복구 5개, 화면 12조합, 새 권장 취소·조리개 ± 연속 동작을 통과했다. 새 자동 검사는 저장 성공 응답과 실제 파일 불일치·읽기 실패·병합 후 재시도를 다룬 3개다. 기존 GN·심도·존 역산·환산·단위·마이그레이션·초안·즐겨찾기·삭제 복구·Markdown 관련 검사는 현재 코드로 95개 묶음에서 실행했다. 이전 모바일 41개 전체를 이번 실행 결과로 재표기하지 않았다.

일반 흐름·화면 조합에서 런타임 콘솔 오류는 없었다. 저장 실패 주입에서는 의도한 저장 오류 로그 1개가 발생했고 UI 복구 후 해소됐다. 현재 탭 Markdown이 현재 Q20III·출력·예상 거리와 일치함도 실제 저장 노트로 확인했다. 전체 계산 Markdown의 새 연속 UI 저장은 이번 추가 검사에서 수행하지 않았으며 기존 자동 검사를 참조한다. 장비 삭제·수정/안전한 즐겨찾기 취소는 기존 현행 자동 회귀를 사용했고 이번 연속 UI 흐름에서 다시 삭제하지 않았다.

실제 iOS/Android 화면 키보드, 실제 야외 햇빛, 한 손 조작, 카메라·플래시 시험 촬영/광량 측정, 장기간·대형 보관함 스트레스는 미검증이다. 예상 계산값과 화면·저장 상태의 일치까지만 결론 낸다. 관찰 자동화의 도달 스크롤은 손가락 드래그 횟수나 실제 사용자 속도가 아니다.
