# 1.4.1 현장 사용 수정 후보 · 설치와 복구

이 후보는 별도 테스트 보관함에서 검증했으며 아직 공개 배포하거나 실사용 보관함에 설치하지 않았다. 이전 1.4.0 배포 승인을 이번 변경의 배포 승인으로 해석하지 않는다.

설치 후보: `dist/photo-field-mobile-1.4.1-field-use-candidate.zip`. 런타임·라이선스·서드파티 고지·이 안내만 포함하며 사용자 `data.json`과 테스트 데이터는 포함하지 않는다. 파일 해시는 `docs/field-use-2026-11-03/package-verification.json`에 기록한다.

## 승인 후 설치

1. Obsidian에서 변경을 저장하고 플러그인을 비활성화한다. 기존 `.obsidian/plugins/photo-field-mobile/` 폴더 전체를 별도 위치에 백업한다. 특히 `data.json`을 보존한다.
2. ZIP의 `photo-field-mobile/` 안에 있는 `main.js`, `manifest.json`, `styles.css`, 라이선스·고지·vendor 파일을 기존 플러그인 폴더로 복사한다. 기존 폴더를 삭제하거나 `data.json`을 덮어쓰지 않는다.
3. 플러그인을 다시 활성화하고 즐겨찾기·거리·장비·마지막 화면을 확인한다. 이 후보에는 1.4.0 대비 데이터 스키마 변경/추가 마이그레이션이 없다. 기존 Saved v2/field v1 및 미래 스키마 보호를 유지한다.
4. 설정 저장 실패가 보이면 저장 위치·권한·동기화 충돌을 먼저 해결한 뒤 화면의 “저장 재시도”를 누른다. 재시도 전에 앱을 닫으면 아직 저장되지 않은 변경은 사라질 수 있다. 성공 응답만 믿지 않고 저장 파일까지 확인하는 방식으로 개선했다.

## 1.4.0으로 복구

플러그인을 끄고 기존 공개 `dist/photo-field-mobile-1.4.0.zip`의 코드·라이선스 파일을 덮어쓴 뒤 다시 활성화한다. 같은 데이터 형식이므로 현재 `data.json`은 유지한다. 데이터 자체가 손상되었을 때만 설치 직전 백업을 복구하며 백업 이후 변경이 사라짐을 확인한다. 실사용 보관함을 테스트 초기화하거나 QA 데이터로 대체하지 않는다.
