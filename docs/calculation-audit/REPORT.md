### 플래시 독립 유도

같은 중심부 노출 조건의 상대 노광량은 `Q=G² p (ISO/100) 2^(−L)/(N² r²)`이다. 적정 조건은 Q=1이므로:

```
Geff = G sqrt(p) sqrt(ISO/100) 2^(−L/2)
d = Geff/N
p_required = (N r/G)² (100/ISO) 2^L
N_required = Geff/r   # 현재 출력 p에서의 필요 조리개
EV = log2(Q) = 2 log2(d/r)
residual(n) = log2((1/n)/p_required)
low = d 2^(−T/2), high = d 2^(T/2)
```

출력 4배·ISO 4배는 거리 2배, f-number 2배는 거리 1/2, 손실 +1stop은 거리 1/√2이다. ±EV의 부호와 거리 경계는 Q로 별도 검산했다. TTL·HSS·바운스·모디파이어·근거리 대형 광원 모드는 정상 GN 결과를 내지 않고 오류를 낸다. 수동 모드라도 실제 광원의 크기/거리 비율이 부적절하면 이 모델은 맞지 않는다. 이 한계를 화면·Markdown에 명시했다.

### 심도 독립 유도·경계

모든 광학 길이를 mm로 둔다. 초점 위치 s의 상거리 `vs=1/(1/f−1/s)`, 임의 물체 거리 u의 상거리 `vu=1/(1/f−1/u)`, 개구 `D=f/N`. 센서상의 착란원은:

```
blur(u) = D abs(1−vs/vu)
```

`blur(u)=c`를 각각 풀면 근·원 경계가 나오고, `blur(∞)=c`가 되는 초점 거리가 H다. 구현의 `h=f²/(N c)`, `H=h+f`, `near=h s/(h+s−f)`, `far=h s/(h−s+f)`와 일치한다. `s≥H`에서만 물리적 원거리 ∞, 이때 전체 심도도 ∞다. H에서 근거리는 H/2다. 유한 far의 산술 오버플로는 오류이며 ∞로 승격하지 않는다.

대표 표의 독립 근·원 계산은 먼저 `vu=vs/(1∓c/D)`를 구한 뒤 결상식으로 u를 복원했다. 무작위 800개는 반환된 경계에서 광선 원뿔의 실제 blur가 c인지 검사하고, 원거리가 ∞이면 `blur(∞)≤c`인지 검사했다. 단순 정·역 함수 왕복은 정확성 근거로 사용하지 않았다.

**극점 주의:** H 바로 앞의 far는 작은 `H−s`로 나누므로 조건수가 급격히 커진다. 입력·H 표현의 1ulp 차이도 거대한 유한값 차이나 수학적 극점의 어느 쪽인지에 영향을 준다. 따라서 인접 부동소수점 검사는 앱이 공개하는 H의 바로 전/같음/바로 후를 구별하는 회귀 검사다. 이 영역의 엄청난 유한 거리를 현실적으로 정밀한 촬영 거리라고 주장하지 않는다. Decimal로도 이를 확인했으며 [pole-conditioning.txt](pole-conditioning.txt)에 실제 입력 부동소수점과 고정밀 극점의 차이를 기록했다. 넓은 epsilon 범위를 ∞로 처리하는 우회는 넣지 않았다.

### 존 역산과 최적성

유한 목표 a<b에서 양 끝의 blur가 같도록 맞추면 `s*=2ab/(a+b)`이다. 산술 평균이 아니다. 각 끝의 blur 제한이 동시에 허용하는 최대 h는 `h*=[2ab−f(a+b)]/(b−a)`이고, 가장 개방된 연속 해는 `N*=f²/(c h*)`이다. 실제 단계는 N* 이상의 목록 중 렌즈 범위 안에 있는 가장 작은 N을 고르고 정방향으로 다시 확인한다. 더 조인 단계에서도 이 초점으로 전체 목표를 포함할 수 있다.

원거리 ∞는 `H≤2a`, `N*=f²/[c(2a−f)]`다. 선택된 실제 단계에서는 그 단계의 H에 초점을 둔다. 원거리 ∞는 임의의 큰 유한 숫자로 바꾸지 않는다.

독립 검사는 초점의 역수 q=1/s 구간 전체에서 `max(blur(a),blur(b))/c`를 연속 삼분 탐색(130회)해 최소 필요 N을 구했다. 구현의 분석식이나 optics를 정답 생성에 쓰지 않았다. 300개 고정 시드 목표에서 이 최솟값, 실제 단계의 최적성, 양 끝 blur를 비교했다. 좁은 2~2.0001m, 가까운 .1~.15m, 넓은 1~1e8m, 먼 1000~1001m와 무한대도 별도 검사했다. 연속 최솟값보다 0.1% 개방한 N은 양 끝 중 적어도 하나를 만족하지 못했다. 구현은 일부 초점 거리를 거칠게 훑은 해를 최적해로 표시하지 않는다.

### 환산·프레임의 의미

`kdim=hypot(36,24)/hypot(w,h)`, `feq=f k`, `Neq=N k`. 같은 입사동공과 대응 CoC·위치·구도·감상 조건에서 원거리 심도를 근사 비교한다. 근접 촬영의 f항·브리딩 때문에 유한 거리의 엄밀한 심도 동일식은 아니다. 명목 1.5/1.6과 실제 센서 치수의 kdim 차이는 버그가 아니다. 예시 APS-C 23.6×15.6mm는 kdim≈1.5294로 명목 1.5와 다르다. 4:3 센서는 대각 환산으로 수평·수직 화각을 동시에 일치시킬 수 없다.

실제 심도는 실제 f,N,c로만 계산한다. 환산 기준만 변경하면 GN 거리·EV는 불변이다. 기본 프레임 폭·높이는 각각 `r w/f`, `r h/f`와 독립 비교했다. 이 핀홀/무한대 초점 프레임 근사는 근접 촬영의 정확한 배율 모델이 아니다. 이 한계를 화면과 저장물에도 추가했다.

## 허용 오차·대표 표

- 일반 수치 비교: `|actual−expected|≤1e−12 + 2e−11|expected|` (출력 단위별 m, mm, degree, EV 또는 비율). IEEE 배정밀도와 테스트 영역의 연산 수보다 충분히 크지만 표시 단위(.01m 등)보다 훨씬 작다.
- 독립 결상에서 경계 blur는 큰 두 상거리의 차를 취하므로 상대 2e−8와 절대 1e−12mm. 이는 경계값의 수치 소거 여유이며 물리적 선명도 허용 범위를 넓히는 값이 아니다.
- 존 연속 최솟값은 독립 반복 탐색·상거리 소거를 포함해 상대 1e−9. 특별히 좁은 고정 구간은 2e−8. 조리개 단계 선택은 오차로 다른 단계를 허용하지 않고 정확히 비교한다.
- 실제 포함 판정은 경계 길이 크기에 비례하는 16×Number.EPSILON(~3.55e−15)만 허용한다. 무한대 목표는 far===Infinity만 인정한다. H의 ∞ 판정에 epsilon 띠는 없다.
- 대표 출력 표는 다른 독립 구현의 읽기 쉬운 검산을 위해 절대 1e−10 + 상대 2e−10을 명시 적용했다. 모든 실제 오차를 숨김 없이 기록했으며 현재 최대 오차는 정상 대표값에서 약 4e−14 수준이다. ∞는 빼기 오차로 비교하지 않고 종류를 정확히 비교한다.
- SVG 좌표는 독립 선형축과 1e−10 viewBox 단위로 비교했다. 문자열 표시는 각 필드의 소수 자릿수로만 비교했다.

[대표 입력 / 독립 기대값 / 실제값 / 절대 오차 / 판정 전체 표](representative-table.md). GN 기본 예, 손실, 출력·조리개 역산, 지원 단계 EV, 두 축 화각·프레임, 심도·과초점·Airy, FF/1.5/1.6 환산, 존의 대표값을 포함한다.

단계 선택에서 필요 p=.36이면 1/2의 +0.473931EV가 1/4의 −0.526069EV보다 작다. 초기에 수동 표 작성 중 1/4로 잘못 적은 기대값은 독립 로그 비교와 경계 `sqrt(.25*.5)=.353553<.36`으로 정정했다. 구현에 맞춰 정답을 변경한 것이 아니며 허용 오차를 늘리지 않았다.

### 검증 도중 진단 정정 기록

초기 테스트 도우미가 Infinity−Infinity를 수치 오차로 비교해 실패했다. 이를 정확한 Infinity 종류 비교로 바로잡고 [최초 로그](before/new-tests.txt)와 [정정 도우미로 확인한 수정 전 4개 실패](before/new-tests-corrected-harness.txt)를 모두 보존했다. 테스트 대상의 공식을 바꾸어 이 실패를 감춘 것이 아니다.

비교 증거 스크립트에서 과거 소스를 import하면서 과거 model 타입 파일을 처음에 빠뜨려 빌드가 한 번 실패했다. [빌드 진단](build-first-attempt.txt)을 보존하고 모델 스냅샷을 보충했다. 그때 낡은 번들로 수행한 강화 화면 검사의 실패도 [기록](ui-first-final-attempt.json)에 남겼다. 수정한 새 번들로 타입·전체 검사·8개 화면 검사·앱 정상 재실행을 통과한 뒤에만 최종 후보에 담았다.

## 기존 저장 결과에 미치는 영향

저장 형식 version:2를 유지하고 입력·장비 표·초안·기존 migrationBackup을 보존한다. 현재 작업에서 데이터 마이그레이션이나 실제 보관함 재저장은 하지 않았다. 기존 마이그레이션 회귀도 전체 테스트에 포함된다. 새 입력 필드를 추가하지 않았다.

기존 JSON은 결과가 아닌 입력을 저장하므로 새 실행에서 재계산된다. 정상 영역의 far는 같은 공식의 연산 순서 변화에 따른 미세한 수치 차이가 있을 수 있고, 극점 바로 전·극단 입력에서는 오류/유한값/권장 단계 판정이 달라질 수 있다. 기존 Markdown 노트는 정적 기록이라 자동 수정되지 않는다. 잘못된 ∞·단계·−0가 담긴 과거 노트가 중요하다면 새 버전에서 같은 입력으로 다시 저장해야 한다. 새 문서는 반올림 전 판정·주평면 거리·역제곱 한계를 명시한다.

## 설치 후보·복구

[검증된 로컬 후보](../../dist/photo-field-mobile-1.3.0-calculation-audit-candidate.zip), [작업 시작 시 바이너리 복구본](../../dist/photo-field-mobile-1.3.0-pre-calculation-audit-recovery.zip). 공개 릴리스나 실사용 설치는 하지 않았다. manifest 버전은 기존 **1.3.0**이며 별도 후보 파일명과 SHA256으로 구별한다. 기존 후보 ZIP을 덮어쓰지 않는다.

[패키지 검증](package-verification.json)과 [SHA256](SHA256SUMS.txt)에 ZIP 내부 파일별 해시·최종 소스 빌드/테스트 앱 설치 파일과의 일치·라이선스·사용자 data.json 제외를 기록한다. 적용 시 기존 플러그인 폴더, 특히 data.json을 백업하고 플러그인을 비활성화한 뒤 후보의 main.js/manifest.json/styles.css만 교체한다. data.json을 교체하지 않는다. 복구본은 같은 세 파일의 작업 전 정확한 바이트다.

## 남은 한계와 미검증 사항

실제 광량계/시험 촬영 보정, 광원의 실제 크기·배광·반사·혼합광, HSS/TTL/바운스 모델은 검증하지 않았다. 실제 렌즈 주평면·동공 배율·근접 배율·포커스 브리딩·왜곡·수차·회절과 기하 착란원의 합성도 계산하지 않는다. 센서 /1500 CoC는 사용자 감상 조건을 보장하지 않는다. 근접 거리의 프레임과 단순 크롭 심도 대응을 정확한 실측값으로 사용할 수 없다.

배정밀도의 전체 양수 영역을 정확 계산한다고 주장하지 않는다. 표현할 수 없는 파생 값과 화각 포화는 오류로 중단한다. H 극점의 먼 거리 수치는 심하게 민감하며 입력 유효 자릿수·모델의 정밀도보다 많은 의미를 부여할 수 없다. UI의 반올림 숫자는 경계 포함의 증거가 아니다.

실제 iOS/Android, 화면 키보드·safe area·VoiceOver·TalkBack·백그라운드·동기화 충돌·센서면 실측 거리와 주평면 보정은 이번 작업의 통과 범위에 없다. 검증된 정상 수치 영역·오류 처리·실제 macOS 모바일 에뮬레이션 연결에 한해서 결론을 낸다.
