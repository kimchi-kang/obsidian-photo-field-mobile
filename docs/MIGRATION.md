# 1.2.0 데이터 마이그레이션과 복구

1.1.0의 `data.json`은 스키마 version1이다. 1.2.0은 version2로 읽고 이후 저장한다. 기존 파일을 설치 시 임의 초기화하지 않는다.

- 유효한 기존 장비의 이름/조건/출처/GN 표/지원 출력/최소 출력과 입력값을 보존한다. 기존 장비에 `legacy-1` 등 안정적인 ID를 부여하며 중복 ID는 구분한다. 이후 이름을 바꿔도 ID는 유지한다.
- 옛 버전은 ‘마지막으로 적용한 장비’를 기록하지 않았으므로 추정으로 장비를 선택하지 않는다. 기존 GN은 **수동 GN 모드**로 복원한다. 장비 목록에서 선택하면 장비 모드가 되고 줌별 표를 연결한다.
- 장비 모드의 선택 ID와 초안, 삭제 되돌리기1개를 함께 저장한다. GN 등 장비값 직접 수정은 수동 모드로 표시한다. 단위 변경은 같은 물리값의 표시 변환이다. 명시적으로 수동↔장비 모드를 바꾸면 별도 보관한 수동 설정을 복원한다.
- 장비 표에 없는 줌에서는 GN=0/측정 줌=0을 ‘자료 없음’ 표식으로 쓰며 계산하지 않는다. 이전 GN 대입/보간 없음. 출력은 바꾸지 않고 미지원 이론값과 가능한 지원 단계를 보여준다.
- 원본 version1 JSON 전체를 `migrationBackup`에 한 번 보관한다. 유효하지 않아 활성 장비로 읽지 못한 오래된 항목도 여기에 남는다. 앞으로의 미지원 스키마 버전은 덮어쓰지 않도록 로드를 거부한다.
- 실사용 보관함 적용 전 원본 `data.json`을 플러그인 내 `backups/`에 별도 복사한다. 이 파일은 공개 저장소·ZIP에 포함하지 않는다.

## 되돌리기

먼저 Obsidian에서 플러그인을 끈다. 현재 `data.json`도 복사해 둔 뒤 `backups/`의 설치 전 파일을 `data.json`으로 복구한다. 같은 시점의 이전 `main.js`, `manifest.json`, `styles.css`도 함께 복구한다. 파일 복구 중 앱이 실행해 덮어쓰지 않게 한 뒤 다시 켠다. 자동 백업이 없으면 version2 JSON의 `migrationBackup` 객체를 별도 JSON 파일로 꺼내 이전 버전의 데이터로 사용할 수 있다. 복구 이후 새로 입력한 변경은 복구 파일에 없으므로 따로 보존해야 한다.

삭제한 장비는 ‘삭제 되돌리기’로 복구할 수 있다(마지막1개, 재진입/재실행 후에도 보존). 다음 삭제로 이전 되돌리기 항목을 대체한다. 작성 중 프리셋은 자동 보존되며 편집 취소 버튼으로 명시적으로 지울 때만 비운다. 다른 장비 편집으로 초안을 대체하려면 먼저 저장하거나 취소해야 한다.

저장 실패 시 오류를 확인하고 ‘설정 다시 저장’을 누른다. 앱을 계속 열어 두어 성공까지 기다린다. 실패 중 OS 강제 종료까지의 복구는 보장하지 않는다. 노트 저장은 설정 저장과 분리되며 기존 Markdown을 덮어쓰지 않는다.
