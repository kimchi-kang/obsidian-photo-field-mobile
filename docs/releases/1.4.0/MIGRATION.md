# 1.4.0 데이터 보존·복구

이번 작업은 실사용 보관함에 설치하지 않았습니다. 검증은 `/private/tmp/photo-field-qa-vault`, 별도 `/private/tmp/photo-field-qa-profile`에서만 수행했습니다.

## 추가되는 데이터

기존 저장 형식 version 2에 `field` 하위 스키마 version 1을 추가합니다. 기존 입력·수동 GN 백업·장비 ID와 사양·장비 편집 초안·장비 삭제 복구·존 목표와 조리개 제한은 유지합니다. field가 없던 데이터는 전체 이전 데이터를 migrationBackup에 보존하고 내 거리 예시만 생성합니다. 기존 migrationBackup은 이전 데이터 안에 함께 보존됩니다.

field에는 촬영/존 즐겨찾기, m 단위 거리 배열과 순서, 간편 화면 선택, 적용 중인 촬영 즐겨찾기의 ID가 저장됩니다. 새 항목은 UUID를 사용하며 초기 거리 ID도 한 번 생성한 뒤 유지합니다. 촬영 조건의 저장 키는 명시적 목록입니다. 화면 펼침 상태·저장 오류·초안·취소 기록은 촬영 즐겨찾기에 포함하지 않습니다.

숫자·문자열·열거값·양수 거리·거리 중복·ID 중복·존 원근 관계를 복원 시 검증하며 잘못된 새 항목은 제외합니다. 지원하지 않는 더 높은 상위 버전 또는 field 스키마는 오류로 로드를 중단하여 저장기를 시작하지 않습니다. 새 데이터로 조용히 덮어쓰지 않습니다.

장비 즐겨찾기는 ID와 사양 서명을 저장합니다. 누락/변경 시 오래된 GN이나 다른 장비로 대체하지 않습니다. 변경된 장비의 실제 지원 출력 목록은 현재 목록으로 읽고 GN 계산은 확인·갱신 전까지 차단합니다. 장비가 없으면 목록도 알 수 없어 단계 이동을 차단합니다. 명시적인 장비 재선택은 현재 장비를 사용하겠다는 선택으로 처리하며 이전 즐겨찾기의 적용 표시를 해제합니다.

기존 LatestWriter의 최신 상태 병합·실패 재시도와 빈 숫자 입력의 마지막 유한값 저장을 유지합니다. 강제 종료 전 디스크 쓰기를 마치지 못하면 마지막 동작까지 보존할 수 있다는 보장은 없습니다.

## 승인 후 설치 전

1. Obsidian을 닫거나 플러그인을 끄고, 사용할 보관함의 `.obsidian/plugins/photo-field-mobile/` 폴더 전체를 별도 복사합니다. 특히 `data.json`을 보관하세요.
2. 후보 ZIP의 `photo-field-mobile/` 안 프로그램 파일과 라이선스를 해당 플러그인 폴더에 복사합니다. 기존 `data.json`은 교체하지 않습니다.
3. 플러그인을 켜고 기존 입력·장비·미완료 초안이 유지되는지 확인합니다. 이번 후보를 공개 BRAT 최신판으로 올리지는 않았습니다.

## 이전 1.3.4로 복구

플러그인을 끈 뒤 기존 `dist/photo-field-mobile-1.3.4.zip`의 프로그램과 **설치 전 보관한 data.json**을 함께 복원합니다. 1.3.4는 새 field 데이터를 이해하지 못하므로 새 데이터를 읽고 다시 저장하게 두지 마세요. 최신 데이터도 별도 보관하면 1.4.0의 즐겨찾기를 나중에 복원할 수 있습니다.

설치 전 백업이 없다면 현재 data.json을 먼저 별도 보관하고 migrationBackup을 확인하세요. 이번 업데이트 직전 데이터가 보존돼 있다면 그 객체 전체가 복구용 data.json입니다. 사용자 데이터를 자동으로 지우거나 덮어쓰는 복구 작업은 수행하지 않았습니다.
