# 1.4.0 통합 사용 흐름 감사·최소 수정

2026-11-02. 기존 1.4.0 미커밋 구현을 기준으로 검사했습니다. 버전 상승과 새 기능 추가 없이 view.ts의 배치·표시·존 적용 스크롤 및 해당 스타일만 수정했습니다. 계산 엔진·존 역산·단위 변환·데이터 스키마·저장 병합은 변경하지 않았습니다. 시작 시의 미커밋 작업과 기존 검증 자료는 그대로 보관했습니다.

## 검사 환경·방법

MIA Study 방식의 별도 macOS Obsidian 1.14.5 보관함 `/private/tmp/photo-field-qa-vault`, 별도 프로필 `/private/tmp/photo-field-qa-profile`. app.emulateMobile(true), Playwright/CDP 모바일 뷰포트와 터치 이벤트를 사용했습니다. 실사용 보관함과 iPhone 미러링은 사용하지 않았습니다. 적용 지침은 `/Users/choikang/Documents/Codex/AGENTS.md`입니다.

현재 코드에서 수정 전 흐름을 새로 수행하고 캡처했습니다. 과거 캡처를 수정 전 증거로 재사용하지 않았습니다. 코드·런타임 원본은 before/에 보존했습니다. 360×800·390×844·844×390, 라이트/다크, 기본/22px rem의 12조합에서 플래시·존 24개 캡처를 생성하고, 수치 검사와 주요 화면 직접 확인을 함께 수행했습니다. 44px 수준 터치 영역·가로 넘침·버튼 중앙 가림 여부·기존 실제 장면의 터치 드래그도 검사했습니다. 전체 접근성 준수나 실제 단말의 키보드 성능을 판정한 연구는 아닙니다.

조작 수는 CDP 터치로 실제 누른 횟수입니다. 화면 밖 컨트롤에는 scrollIntoView를 사용하고 전/후 scrollTop을 기록했습니다. 따라서 ‘스크롤 이동’은 컨트롤 접근을 위한 위치 보정 횟수이며 물리적인 손가락 스와이프 수와 같다고 간주하지 않습니다. 속도·시간을 사용자 연구로 측정하지 않았습니다.

## 재현한 불편과 수정

1. **출력 조절 뒤 즐겨찾기로 돌아가는 왕복**: 수정 전 390px 기본 화면에서 약하게 버튼으로 399.5px 내려갔다가 다음 즐겨찾기로 399.5px 올라와야 했습니다. 출력 조절을 결과·권장 출력과 같은 영역에 모으고, 변경 없는 적용 내역·반복 요약·간편 화면의 상세 바로가기를 정리했습니다. 만료 안내는 관련 출력 조작 다음으로 옮겨 버튼 위치를 밀어내지 않게 했습니다. 수정 후 1~4번 연속 흐름에서 위치 보정과 자동 이동이 모두 0회입니다.
2. **변경 내역의 출력 표기**: ‘출력 8 → 16’은 숫자 증가를 출력 증가로 읽기 쉬웠습니다. ‘출력 1/8 → 1/16’, ‘실제 조리개 f/4 → f/5.6’, 거리 단위·장비 이름·조건의 사용자용 표기로 바꿨습니다.
3. **존 목표 흐름보다 먼저 보이는 현재 거리·촬영 취소**: 목표를 적용하기 전에 관계가 낮은 조작을 거치고 제안까지 내려가야 했습니다. 목표 선택·제안·명시적 적용을 우선 배치하고 현재 초점 거리 버튼은 제안 다음으로 이동했습니다. 촬영 조건 취소는 플래시/상세에서 계속 접근할 수 있습니다. 390px 기본에서 목표부터 적용까지 2탭·스크롤 0회입니다.
4. **큰 글씨의 존 적용 후 위치 이동**: 360×800·22px rem에서 적용 직후 scrollTop이 382 → 597.5로 변해 상태·제안이 화면 위로 밀렸습니다. 적용 중 기존 스크롤 위치를 유지해 최종 382 → 382, 자동 이동 0px로 확인했습니다. 12조합 모두 적용 직후 자동 이동이 없습니다.

## 화면 크기별 남는 스크롤

두 테마의 결과는 같습니다. 아래는 즐겨찾기 → 거리 → 권장 출력 → 약하게 → 강하게 → 존 화면 → 존 목표 → 적용을 연속 수행한 결과입니다. 스크롤을 제외한 터치는 모든 조합에서 8회입니다. 가로 화면과 큰 글씨는 화면 전체를 축소하지 않고 세로로 읽습니다.

| 화면 | 기본 글씨 | 큰 글씨 |
|---|---|---|
| 390×844 | 위치 보정 0회, 왕복 0회 | 위치 보정 3회, 플래시→존 전환 중 왕복 1회 |
| 360×800 | 출력 조절 접근과 존 탭 복귀 각 1회, 왕복 1회 | 위치 보정 3회, 왕복 1회 |
| 844×390 | 위치 보정 5회, 플래시→존 전환 중 왕복 1회 | 위치 보정 5회, 왕복 1회 |

이는 남는 화면 제약입니다. 작은 화면에서 모든 조작을 한 화면에 축소해 넣지 않았습니다. [전체 이동 기록](after/matrix.json). 계산 결과 확인↔출력 약/강 조절 사이의 반복 왕복은 모든 조합에서 없었고, 390×844 기본 글씨에서는 상단 즐겨찾기까지 이동 없이 이어집니다. 실제 iOS/Android의 네이티브 키보드·접근성·안전영역·동기화·강제 종료 복원·실제 플래시 노출은 미검증입니다.

## 회귀·상태 일관성

- strict 타입 검사·빌드, 자동 회귀 **92개** 재실행 통과: GN·심도·존·환산·지원 출력 경계·데이터 마이그레이션·저장·노트 등. [결과](after/tests.txt)
- 현재 코드로 기존 모바일 **41묶음** 재실행 통과: cm/m·소수 커서·즐겨찾기·초안·삭제 복구·저장 실패 재시도·현재 탭/전체 Markdown·오프라인·장면 드래그·슬라이더. [로그](regressions.log)
- 닫기·재진입 6회에서 등록 이벤트 수는 매번 143개로 일정했습니다. 이전 쓰기를 완료한 뒤 거리 버튼 한 번에 persist 1회·실제 쓰기 1회·남은 대기 없음. [기록](after/lifecycle.json)
- 연속 흐름과 추가 실제 장비 UI의 콘솔 오류 없음. 저장 실패 검사의 의도적 외부 경계 오류는 실패 메시지·재시도로 별도 확인했습니다.
- 원래 검사 결과를 그대로 새 코드의 통과로 간주하지 않고 재실행했습니다. 과거 결과는 덮어쓰지 않았습니다. 테스트의 변경 내역 기대 문구만 실제 f/ 표기에 맞췄습니다.

## 후보·재현

`dist/photo-field-mobile-1.4.0-integration-candidate.zip`은 현재 소스 빌드·검사 보관함의 프로그램과 바이트 단위로 일치합니다. MIT·원작 라이선스·고지·설치 안내를 포함하고 사용자 data.json은 제외합니다. 기존 첫 구현 ZIP은 그대로 보관했습니다. 데이터 스키마 변경이 없으므로 기존 [마이그레이션·복구 안내](../MIGRATION.md)가 유효합니다.

```
npm run build
npm test
PHASE=after node --import tsx tests/integration-audit.mjs
PHASE=after node --import tsx tests/integration-zone-anchor.mjs
node tests/integration-equipment.mjs
node tests/integration-regressions.mjs
node tests/integration-restart.mjs prepare
# 전용 프로필의 Obsidian만 다시 실행한 뒤:
node tests/integration-restart.mjs verify
python3 tests/package-integration.py
```

before 자료는 원본 그대로 보관하며 현재 코드로 다시 덮어쓰지 마세요. 최종 소스·ZIP 검증과 지문은 [package-verification.json](package-verification.json)에 있습니다. 실사용 설치·공개 배포는 미승인 상태라 수행하지 않았습니다.
