# 실사용 설정 변경 추가 조사

사용자는 실사용 설정을 직접 변경하지 않았다고 확인했다. 이를 사용자 조작으로 설명하지 않는다. 실사용 검사 중 의도하지 않은 설정 변경이 발견됐으며 원인은 아직 확정하지 못했다.

## 확인한 근거

- 당시 도구 호출 기록에서 실사용 조작은 리본 열기·플래시 탭 클릭·원래 존 탭 클릭·화면 닫기/재열기·명령 팔레트 열기/닫기에 한정됐다. 계산값 입력·프리셋 변경·노트 생성/삭제·실패 주입 호출은 없었다.
- 창 제목과 디스크의 탭 상태는 바뀌었지만, 컴퓨터 제어의 캡처/접근성 하위 트리는 이전 상태를 반복했다. 따라서 오래된 대상을 참조한 자동 조작의 오작동 가능성을 배제할 수 없다. 도구가 의도한 컨트롤 대신 실제 어떤 컨트롤에 이벤트를 전달했는지는 기록만으로 확정하지 못한다.
- 검사 전후 입력7개 키(aperture, cameraDistance, flashDistance, tab, zoneNear, zoneFar, zoneInfinity)가 달랐다. 장비·초안 등 입력 이외 데이터는 같았다. 실제 값과 파일 경로는 ignored dist/post-release-private에만 보관한다.
- UTC11:29:21의 읽기에서는 검사 전 파일과 바이트가 같았으나, 이후 읽은 변경 파일의 수정 시각은 UTC11:29:08이었다. 수정 시각만으로 실제 변경 순서나 QA 이전/이후 발생을 판단할 수 없다. 처음에 파일 수정 시각이 QA 시작 전이라는 점을 언급한 것은 원인/발생 순서를 증명하지 못한다.
- QA와 실사용 data.json은 서로 다른 파일이고, 변경된 실사용 입력은 QA 입력과도 일치하지 않았다. 실사용 설정을 QA에 복사하지 않았다.
- 영향받은 파일 이름으로 기존 bird/cloudd/fileproviderd 로그를 읽었으나 일치 항목을 얻지 못했다. 이는 동기화를 배제하거나 원인으로 확인하는 증거가 아니다.

## 별도 환경 재현

공개1.3.4 실행 파일을 유지한 전용 QA ItemView에서 독립 합성 설정을 사용했다. 실제 사용자 설정 스냅샷을 테스트 입력으로 사용하지 않았다.

- 숫자 입력 포커스를 둔 채4탭 전환100회: 탭 이외 모든 입력·장비 동일.
- 실제 ItemView 닫기→명령으로 다시 열기15회: 모든 계산값·장비 동일.
- 디스크 저장 입력과 런타임 입력 일치.
- plugin.update 추적에서 값이 실제 달라진 키는 tab뿐. pageerror0.

원자료: [navigation-results.json](investigation/navigation-results.json), [mutation trace](investigation/navigation-trace.json), [실행 로그](navigation-run.txt). 재현 명령은 `node tests/post-release-navigation.mjs`이며 전용 QA 보관함 이외 연결을 거부한다.

이는 정상적인 탭/재진입 경로에서 자동 변경을 재현하지 못했다는 결과다. 관측이 불일치했던 실사용 컴퓨터 제어 경로까지 안전하다고 입증하지 않는다. 새 제품 결함으로 확정하거나 불필요하게 코드를 수정·버전 상승·재배포하지 않았다.

## 복구 준비와 남은 일

검사 전 스냅샷으로 복구 후보를 만들었다. 현재 파일이 예상 해시에서 다시 바뀌면 중단하도록 비교 계획을 준비했고, 차이는 위7개 입력뿐이며 장비는 유지된다. 후보와 상세 변경표는 로컬 ignored dist/post-release-private/recovery-candidate.json, recovery-plan.json에 있다. **실사용 파일에는 적용하지 않았다.**

앞선 실사용 계산값 변경 금지 범위를 고려해 복구 적용 의사를 확인해야 한다. 적용 시 오래된 메모리 상태가 다시 저장되지 않도록 정상적인 앱 응답/종료·재진입을 확보한 뒤 진행해야 한다. 임의 강제 종료는 하지 않는다.

남은 항목: 안전한 설정 복구 여부 결정, 정상적인 화면 관측 상태에서 실사용4탭·재진입 확인, 의도치 않은 변경의 원인 확정. 현재 상태를 배포 후 확인 완료로 표시하지 않는다.
